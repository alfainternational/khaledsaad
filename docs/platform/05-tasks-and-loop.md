# 05 — المهام وإقفال الحلقة

> يعالج B3: ٦ تقارير مليئة بالتوصيات و**٠ مهام**.
> هذا أهم تغيير منتَجي في الوثيقة كلها.

## 1. الأطروحة

**وحدة المنتج ليست التقرير، بل المهمة.**

اليوم ينتهي المنتج عند النقطة التي تبدأ عندها القيمة. سبب الرجوع الحالي
«شغّل تشخيصًا» — حدث يقع مرة كل عدة أشهر. سبب الرجوع المطلوب
«تابع خطتك» — حدث أسبوعي. هذا الفرق هو الفرق بين أداة ومنصة.

## 2. المفاجأة السارّة: بنية المهمة موجودة أصلًا

كل توصية في تقاريرك تحتوي فعلًا على:

| الحقل الموجود | ما يقابله في المهمة |
|---|---|
| الناتج | `deliverable` |
| تعريف الإنجاز | `definition_of_done` |
| أول خمس دقائق | `first_step` |
| الفشل المتوقع ومخرجه | `known_pitfall` |
| المؤشر | `success_metric` |
| المدة (خلال ٣٠ يومًا) | `due_at` |
| الأثر / الجهد | `impact` / `effort` |

**ينقصها حقلان فقط: `status` و`owner`.** المنتج على بُعد جدول واحد من إقفال حلقته.

## 3. التوليد تلقائي، لا زر اختياري

زر «حوّلها إلى مهمة» يفترض أن المستخدم يعرف أنه يحتاجها — وهو جاء ليخبره أنت.

```php
final class MaterializeTasksFromReport {
    public function handle(ReportGenerated $e): void {
        foreach ($e->report->recommendations as $rec) {
            Task::firstOrCreate(
                ['recommendation_id' => $rec->id],          // idempotent (INV-9)
                [
                    'project_id'         => $e->report->project_id,
                    'status'             => TaskStatus::Suggested,
                    'due_at'             => now()->addDays($rec->horizon_days),
                    'definition_of_done' => $rec->dod,
                    'success_metric'     => $rec->metric,
                    'first_step'         => $rec->first_step,
                    'impact'             => $rec->impact,
                    'effort'             => $rec->effort,
                    'sort_key'           => $rec->priorityRank(),
                ]
            );
        }
    }
}
```

الحالة الابتدائية `suggested` لا `open`: الخطة تُقترح كاملة، والمستخدم **يتبنّى** ما يريد
بضغطة. هكذا لا نغرقه بعشرين مهمة، ولا نخفي عنه شيئًا.

```php
enum TaskStatus: string implements HasLabel {
    case Suggested = 'suggested';   // مقترحة من تقرير
    case Adopted   = 'adopted';     // تبنّاها المستخدم
    case InProgress = 'in_progress';
    case Done      = 'done';
    case Dropped   = 'dropped';     // مع سبب — إشارة تعلّم ثمينة
}
```

## 4. الترتيب من خريطتك القائمة

خريطة «الأثر مقابل الجهد» موجودة في التقرير. اجعلها هي الترتيب الافتراضي للمهام:
`أثر عالٍ + جهد بسيط` أولًا. رسالة الواجهة تبقى كما هي: «ابدأ من الخلية الخضراء».

## 5. صفحة «الخطة والمهام» (مسار حقيقي، لا إعادة توجيه — B1)

```
هذا الأسبوع        ← مستحقة أو متأخرة، مرتبة بالأولوية
مقترحة عليك        ← suggested، مع مصدر كل مهمة (أي تقرير)
قيد التنفيذ
منجزة              ← مع أثرها على درجة الجاهزية
```

كل مهمة تفتح على: أول خمس دقائق، تعريف الإنجاز، المؤشر، الفشل المتوقع، والتقرير الأصل.
عند الإنجاز: «ما الرقم الآن؟» — يحدّث حقيقة مرتبطة، فتتحرّك الدرجة، فتُغلق الحلقة فعليًا.

## 6. النبض الأسبوعي — يصبح له ما يقوله

ميزة «النبض الأسبوعي» موجودة لكنها بلا محتوى لأن لا مهام. بعد هذا التغيير:

```
ما تغيّر:      مهمتان منجزتان · جاهزية المشروع ٣٣ ← ٤١
ما تأخّر:      «حدّد مهمة واحدة للتعاقد» متأخرة ٣ أيام
خطوة الأسبوع: [أثر عالٍ · جهد بسيط]  ابدأ بـ…
```

**قاعدة:** لا يُرسل نبض بلا محتوى. رسالة فارغة أسبوعية تُدرّب المستخدم على التجاهل.

## 7. مؤشر الحلقة

المؤشر الحاكم للمنتج:

> **نسبة المستخدمين الذين أنجزوا مهمة واحدة على الأقل خلال ٣٠ يومًا من أول تقرير.**

من أنجز مهمة رأى أثرًا حقيقيًا، ومن رأى أثرًا يجدّد. تابعه في `13-observability.md`.

## 8. اختبارات

```php
it('ينشئ مهامًا تلقائيًا عند توليد تقرير');
it('لا يكرّر المهام عند إعادة توليد نفس التقرير');
it('يرتّب المهام بالأثر مقابل الجهد');
it('يحدّث درجة المشروع عند إنجاز مهمة');
it('لا يرسل نبضًا أسبوعيًا بلا محتوى');
```
