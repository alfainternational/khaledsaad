# 03 — الدرجات

> يعالج العطل A3 (56 / 33 / 83 / 72 / 52 لنفس المشروع) والثابت INV-2.

## 1. درجتان فقط، باسمين مختلفين، لا ثالث لهما

| الدرجة | النطاق | المصدر | التسمية في الواجهة |
|---|---|---|---|
| **درجة جاهزية المشروع** | المشروع كله | `project_scores` | «جاهزية المشروع» |
| **درجة التشخيص** | تقرير واحد | `reports.score` | «درجة هذا التشخيص» |

**ممنوع:** كلمة «الدرجة» مجرّدة، وممنوع عرض `/100` لدرجتين مختلفتين متجاورتين
دون تسمية تفرّق بينهما. الالتباس نفسه هو العطل، لا الأرقام.

## 2. الدرجة تُحسب مرة وتُخزَّن

```php
// migration: project_scores
$t->foreignId('project_id')->index();
$t->unsignedTinyInteger('score');       // 0..100
$t->string('band');                     // enum: scattered|forming|focused|mature
$t->string('formula_version');          // 'v3'
$t->string('inputs_hash');              // بصمة الحقائق والتقارير الداخلة
$t->json('breakdown');                  // لكل محور: raw, max, weight, contribution
$t->timestamp('computed_at');
```

**لماذا كل حقل:**
- `formula_version` — بدونه، تعديل المعادلة يغيّر معنى الدرجات القديمة بصمت،
  فيرى المستخدم رقمه تحرّك دون سبب. عند تغيّر النسخة: أعِد الحساب صراحةً وأعلِن التغيير.
- `inputs_hash` — يخبرك إن كانت الدرجة لا تزال صالحة دون إعادة حساب.
- `breakdown` — يغذّي عرض الشفافية (البند 5) دون إعادة حساب في العرض.

```php
final class ScoreReader { public function for(Project $p): ProjectScore; }   // القراءة الوحيدة
final class ScoreCalculator { public function compute(Project $p): ProjectScore; }  // الكتابة الوحيدة
```

يُعاد الحساب بحدث فقط: `ReportGenerated`، `FactChanged`، `TaskCompleted`، أو ترقية نسخة المعادلة.

## 3. النطاقات (Bands)

عرّفها مرة واحدة كـ enum بعتبات صريحة، وترجمتها في `lang/`:

```php
enum ScoreBand: string implements HasLabel {
    case Scattered = 'scattered';   // 0–39   «مبعثر»
    case Forming   = 'forming';     // 40–59  «يتشكّل»
    case Focused   = 'focused';     // 60–79  «مركَّز»
    case Mature    = 'mature';      // 80–100 «ناضج»
}
```

نفس العتبات تُستخدم في الويب وFlutter — تصل من الـ API، لا تُكرَّر في Dart.

## 4. علاقة الدرجتين — تُشرح في الواجهة لا في الكود فقط

تحت درجة المشروع، سطر واحد ثابت:

> جاهزية المشروع تُلخّص كل تشخيصاتك ومهامك المنجزة.
> درجة كل تشخيص تخصّ ذلك المحور وحده، لذلك تختلف عنها.

هذا السطر يحلّ العطل A3 من جهة المعنى، بينما يحلّه القسم 2 من جهة البيانات. **كلاهما مطلوب.**

## 5. الشفافية — احتفظ بها، غلّفها

المعادلة الخام `104.4 ÷ 126.0 × 100 = 83` ميزة نادرة، لكن عرضها كما هي خطأ عرض:

```
٨٣ من ١٠٠ — ناضج
جمعت ١٠٤٫٤ نقطة من ١٢٦ نقطة ممكنة.
▸ كيف حُسبت؟   ← <details> يفتح جدول breakdown لكل محور
```

## 6. النزاهة المعرفية

الدرجة تحمل دائمًا **مستوى ثقة** مشتقًا من ثقة الحقائق الداخلة فيها (`04-project-facts.md`):

```
٨٣ · ثقة متوسطة — مبنية على ٩ معلومات مؤكَّدة و٣ تحتاج تأكيدك.  [أكّدها →]
```

هذا يمدّ ميزتك القائمة («مدعوم بدليل» / «اجتهاد يحتاج تأكيدك») إلى الدرجة نفسها،
ويحوّل نقص المعلومة من ضعف مخفيّ إلى دعوة صريحة لفعل مفيد.
