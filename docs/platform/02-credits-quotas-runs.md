# 02 — الميزانيات الثلاث، البوابة، والتشغيل

> هذا الملف يعالج العطل الأخطر في التدقيق (A1، A2، A4) وثوابت INV-1، 4، 5، 8، 9.

## 1. الخطأ الجذري: ثلاث ميزانيات مختلفة بلغة واحدة

النظام يتعامل مع **ثلاثة أنواع منفصلة تمامًا** من «عدم القدرة على التشغيل».
دمجها في رسالة واحدة هو ما أنتج التناقض المرصود (`99967` مقابل `0`).

| # | الميزانية | تخصّ | من يتحكم بها | لغة الرسالة | الإجراء المتاح |
|---|---|---|---|---|---|
| **B1** | **رصيد المستخدم** | المستخدم | المستخدم (شراء) | «رصيدك» | اشترِ / رقِّ الخطة |
| **B2** | **حصة الخطة** | الاشتراك | الخطة والفترة | «خطتك تسمح بـ…» | رقِّ الخطة / انتظر التجديد |
| **B3** | **قدرة مزوّد الذكاء** | **نحن** | نحن (اشتراك API، حد المعدل، انقطاع) | «تعذّر التشغيل لأسباب لدينا» | **لا شيء — نحن نتولّاه** |

### القاعدة الحاكمة (INV-8)

> **عطل B3 لا يُصاغ أبدًا بلغة B1 أو B2.**
> المستخدم لا يعرف ما هو «رصيد API»، ولا يجب أن يُطلب منه فعل شيء حياله،
> ولا يجوز أن يُفهم أنه هو المقصّر. عبء الاعتذار علينا لا عليه.

| الحالة | ✅ الصحيح | ❌ الممنوع |
|---|---|---|
| نفاد اشتراك API | «تعذّر التشغيل لأسباب لدينا. إجاباتك محفوظة وسنشغّلها تلقائيًا فور الجاهزية — سنُشعرك.» | «رصيدك غير كافٍ. تحتاج 5 ولديك 0.» |
| حدّ معدل المزوّد | «الطلب مرتفع الآن. دورك محفوظ، ونشغّلها خلال دقائق.» | «فشل التحليل» |
| رصيد المستخدم فعلًا صفر | «تشغيل هذه الأداة يكلّف 5 أرصدة، ورصيدك 0.» + زر شراء | إخفاء التكلفة حتى النهاية |

## 2. رصيد المستخدم — دفتر أستاذ واحد (INV-1)

```php
// migration: credit_entries
$t->id();
$t->foreignId('account_id')->index();
$t->integer('amount');                       // موجب إيداع، سالب خصم
$t->string('kind');                          // purchase|grant|plan_refill|debit|refund|expiry
$t->nullableMorphs('reference');             // Run, Consultation, Invoice…
$t->string('idempotency_key')->unique();     // INV-9
$t->json('meta')->nullable();
$t->timestamp('created_at');
// جدول مساعد: credit_holds (account_id, amount, expires_at, released_at, run_id)
```

```php
final class CreditWallet
{
    public function balance(Account $a): int;                 // مادّي مُحدَّث داخل نفس الـ transaction
    public function available(Account $a): int;               // balance - holds النشطة
    public function hold(Account $a, int $amount, string $key): CreditHold;
    public function settle(CreditHold $h, int $actual): void; // يخصم الفعلي ويحرّر الباقي
    public function release(CreditHold $h): void;
    public function credit(Account $a, int $amount, string $kind, string $key): void;
}
```

**قواعد:**
- الخصم يحدث **بعد** نجاح التشغيل، لا قبله. قبله **حجز** فقط.
- فشل من نوع B3 ⇒ `release()` كاملًا. المستخدم لا يدفع ثمن عطلنا. أبدًا.
- كل حجز له `expires_at`؛ مهمة مجدولة تحرّر الحجوزات المعلّقة.
- التسوية والخصم في `DB::transaction` واحدة مع تحديث حالة الـ run.

## 3. البوابة — `Preflight` (INV-4)

```php
final class Preflight
{
    public function gate(Account $a, Runnable $r, Project $p): PreflightResult;
}

enum PreflightOutcome {
    case Ready;               // ابدأ
    case PartialBudget;       // يكفي لبعض الأدوات — اعرض الحزمة الممكنة
    case InsufficientCredits; // B1 — إجراء للمستخدم
    case PlanLimited;         // B2 — إجراء للمستخدم
    case ProviderUnavailable; // B3 — لا إجراء للمستخدم، نحن نتولّاه
}
```

### تُستدعى في ثلاث نقاط إلزامية

1. **قبل السؤال الأول** — وتُعرض النتيجة والتكلفة صراحةً.
2. **عند كل حدود خطوة** — فحص خفيف مخبّأ (cache) لالتقاط تغيّر الحالة أثناء الإجابة.
3. **عند التنفيذ** — الفحص الملزِم قبل استدعاء المزوّد.

### شاشة ما قبل البدء (إلزامية لكل تدفق)

```
هذا التشخيص: ١٢ سؤالًا · ~٦ دقائق · يكلّف ٥ أرصدة (رصيدك: ٤٠)
الاستشارة الشاملة: ١١ أداة · ٥٩ رصيدًا · نبدأ بـ ٤ أدوات ضمن رصيدك؟
```

هذا وحده يمنع تكرار A1. **ممنوع بدء تدفق دون هذه الشاشة.**

## 4. الاستشارة متعددة الأدوات

```php
$hold = $wallet->hold($account, $plan->totalCost(), $idempotencyKey);
try {
    $results = $orchestrator->run($plan);       // كل أداة لها idempotency key فرعي
    $wallet->settle($hold, $results->actualCost());
} catch (ProviderUnavailable $e) {
    $wallet->release($hold);                     // B3: لا خصم إطلاقًا
    $consultation->markResumable($e->retryAfter());
}
```

- ترتيب التنفيذ **بالأثر تنازليًا**، فإن نفدت الميزانية أُنجزت الأهم.
- نجاح جزئي حالة صالحة: تقرير عن الأدوات التي نجحت + «٧ أدوات متبقية، شغّلها لاحقًا».
- ممنوع «الكل أو لا شيء» في تجربة المستخدم، حتى لو كانت المعاملة المالية ذرّية.

## 5. دورة حياة الـ Run (INV-5)

```
draft → answering → ready_to_run → queued → running
                                      ↓
        ┌─────────────────────────────┼──────────────────────────┐
     completed                 awaiting_capacity            needs_user_action
   (تقرير + مهام)          (B3 — تلقائي، نُشعِر)        (B1/B2 — بانتظار المستخدم)
```

**لا توجد حالة `failed` نهائية تُعرض للمستخدم.** الفشل التقني يُخزَّن في
`run_attempts` للتشخيص الداخلي، والمستخدم يرى دائمًا حالة قابلة للاستئناف.

```php
// run_attempts: run_id, attempt, provider, status, error_class,
//               error_detail, tokens_in, tokens_out, cost, duration_ms, created_at
```

- `awaiting_capacity` ⇒ إعادة محاولة تلقائية بتراجع أسّي مع jitter، وسقف محاولات،
  ثم إشعار عند النجاح: «تقريرك جاهز — اعتذارنا عن التأخير.»
- استئناف الإجابات مضمون: `answers` مرتبطة بالـ run، ومنفصلة عن نتيجة التشغيل.
- **مهمة ترحيل فورية:** كل run بحالة `failed` حاليًا يُرحَّل إلى `ready_to_run`
  ويُدرَج في الطابور. تلك الإجابات الستون أثمن بيانات لدينا.

## 6. طبقة مزوّد الذكاء (B3)

```php
interface AiProvider {
    public function name(): string;
    public function health(): ProviderHealth;   // ok | degraded | exhausted | down
    public function complete(AiRequest $r): AiResponse;
    public function estimateCost(AiRequest $r): int;
}
```

**مطلوب إلزاميًا:**

- **Circuit breaker**: بعد N أعطال متتالية يفتح الدارة، فيتحوّل الاستقبال إلى
  `awaiting_capacity` مباشرة بدل استنزاف المحاولات.
- **مراقبة الحصة استباقيًا**: مهمة دورية تقرأ رصيد/حصة المزوّد.
  عند نزوله تحت عتبة (مثلًا ٢٠٪) ⇒ تنبيه تشغيلي **قبل** أن يشعر المستخدم.
  **العطل الذي حدث كان يجب أن يصل إليك قبل أن يصل إلى مستخدم.**
- **مزوّد احتياطي**: `fallback_chain` في الإعداد. تدهور الجودة أفضل من التوقف.
- **وضع محدود**: عند `exhausted` يستمر كل ما لا يحتاج ذكاءً (عرض التقارير القديمة،
  المهام، الأسئلة، الحفظ) — يتوقف التوليد وحده، مع شريط علوي صادق.
- **سقف إنفاق يومي** قابل للضبط، وتنبيه عند تجاوز التوقّع.
- كل استدعاء يسجّل التكلفة والزمن في `run_attempts` — لمعرفة هامش كل أداة فعليًا.

## 7. لوحة `/admin` — ما يجب أن تعرضه

- صحة المزوّد وحصته المتبقية والاتجاه (لمنع تكرار العطل).
- الـ runs بحالة `awaiting_capacity` وأعمارها.
- الإنفاق اليومي مقابل السقف، وتكلفة كل أداة، والهامش مقابل سعرها بالأرصدة.
- طابور المراجعة البشرية وأعمار الطلبات مقابل الـ SLA.
