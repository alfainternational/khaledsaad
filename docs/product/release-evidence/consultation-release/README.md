# دليل إصدار الاستشارة الموحدة

هذا الإصدار يجعل «ابدأ تشخيص مشروعك» نقطة الدخول الأساسية في الويب وFlutter، مع بقاء الأدوات الإحدى عشرة مكوّنات تشخيص داخلية ومسارات متقدمة للمستخدم الخبير.

## عقد الإصدار

- قاعدة Laravel هي المصدر الوحيد لاختيار السؤال والنطاق والثقة والتعارضات.
- كتالوج الأسئلة والوحدات مُصدّر بإصدارات؛ المنشور مقفل وأي تعديل يبدأ بمسودة مستقلة.
- الإجابة المجهولة لا تُحوّل إلى صفر، بل تسجل فجوة معرفة معلنة.
- لا يبدأ التقرير مع تعارض مفتوح، ولا تُنشر توصية بلا سبب وأثر وخطوات ومسؤول وموارد ومدة ومؤشر وشروط نجاح وإيقاف ومخاطر وثقة.
- ملفات الأدلة تحتاج موافقة صريحة، وتُخزن في القرص الخاص، ويمكن حذفها أو تصدير بيانات الجلسة.
- الويب وFlutter يستخدمان واجهة API نفسها ويستأنفان الجلسة نفسها.

## بوابة التحقق والتسليم

من جذر المشروع:

```powershell
powershell -ExecutionPolicy Bypass -File deploy/verify-consultation-release.ps1
```

للتطبيق على خادم إنتاج بعد ضبط `APP_ENV=production`:

```powershell
powershell -ExecutionPolicy Bypass -File deploy/verify-consultation-release.ps1 -Apply
```

الخيار `-Apply` ينشئ نسخة SQL احتياطية، يدخل وضع الصيانة، ينفذ الترحيلات الإضافية، ينشر الكتالوج، يبني الكاش، يعيد تشغيل الطابور، ثم يعيد الموقع للعمل حتى عند فشل خطوة لاحقة.

## مخرجات Android

- APK: `mobile/build/app/outputs/flutter-apk/app-release.apk`
- AAB: `mobile/build/app/outputs/bundle/release/app-release.aab`

يتطلب نشر iOS النهائي توقيع Apple وشهادة توزيع وملف Provisioning صالحين على macOS؛ الكود والمشروع جاهزان للتحليل والاختبار من هذا المستودع، لكن عملية توقيع App Store ليست قابلة للتنفيذ من Windows.
