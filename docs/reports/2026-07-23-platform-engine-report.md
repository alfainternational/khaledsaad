## 1. تصحيح التقارير السابقة

التقرير التنفيذي السابق («المشروع متوقف بسبب عدم توفر المواد المصدرية»، ثم
«حزمة تخطيط غير جاهزة للبرمجة») لم يعد ينطبق. تلك الأحكام صدرت على مرآة فارغة
ثم على وثائق تخطيط، لا على الكود الحالي.

| ما قيل سابقًا | الحالة الفعلية اليوم |
|---|---|
| لا يوجد كود | 90+ ملف PHP وDart، 38 اختبار PHP و11 اختبار Flutter ناجحة |
| DeepSeek غير مستخدم | مستخدم في خط أنابيب من 10 مراحل مع وضع JSON وتسجيل تكلفة |
| Backlog مختل الصفوف | لم يُعتمد؛ نطاق v1 محسوم في `ADR-001` بدل جدول Excel |
| بنية غير محسومة | محسومة ومنفذة: Laravel 13 + Blade + MySQL + Flutter |
| «11 أداة» ادعاء تسويقي | 11 أداة في قاعدة البيانات، 4 مشغّلة فعليًا و7 بحالة «قريبًا» صريحة |

## 2. ما بُني

### طبقة الذكاء الاصطناعي

| الملف | الدور |
|---|---|
| `app/Contracts/AI/ArtificialIntelligenceGateway.php` | عقد بأربع دوال: `run` / `stream` / `provider` / `modelForTier` |
| `app/Support/AI/AIRequest.php` | طلب يحمل المخطط والمستوى والمرحلة |
| `app/Support/AI/AIResponse.php` | نتيجة تحمل التكلفة والزمن والرموز وسبب الإنهاء |
| `app/Support/AI/DeepSeekGateway.php` | `response_format: json_object` + بث SSE + حساب التكلفة |
| `app/Support/AI/JsonSchemaValidator.php` | مُتحقق مخططات بلا تبعية خارجية |
| `app/Support/AI/StructuredRunner.php` | تحقق + إعادة محاولة مصححة + تسجيل استهلاك |

التوسعات الثلاث المطلوبة نُفذت: وضع JSON، وإرجاع التكلفة والزمن، ودالة البث.

### خط الأنابيب

عشر مراحل في `app/Services/Tools/ToolRunPipeline.php`:

```
entitlement → snapshot → extraction → baseline → gaps
→ sections → consistency → synthesis → persist → notify
```

المراحل الحتمية (اللقطة، الدرجة، الحفظ) لا تلمس الذكاء الاصطناعي إطلاقًا.
لذلك فشل المزود يُنتج تقريرًا جزئيًا يحتفظ بالدرجة وكل الإجابات — وهذا مثبت باختبار.

### قاعدة البيانات

23 جدولًا عبر 7 هجرات: مساحات العمل، المشاريع وملفاتها، الأدوات وإصداراتها
وحقولها وبرومبتاتها، التشغيلات وإجاباتها ومراحلها ومرفقاتها، التقارير وأقسامها
ونتائجها وتوصياتها، المهام والمؤشرات، وسجل استهلاك الذكاء الاصطناعي.

### الويب والتطبيق

55 مسارًا: 24 مسار ويب، 25 مسار API، وبقية المصادقة.
تطبيق Flutter بعشر شاشات تقابل صفحات الويب واحدة بواحدة.

## 3. ضمان التطابق بين الويب والتطبيق

التطابق ليس اتفاقًا يدويًا بل خاصية بنيوية:

```
ToolRunService  ─┬─→ web ToolRunController  ─→ Blade
   (قواعد العمل) └─→ api RunController      ─→ JSON ─→ Flutter
RunPresenter    ─┴─→ نفس المصفوفة للطرفين
```

اختبار `ApiParityTest` يقارن مخرج الـAPI بمخرج العارض المستخدم في الويب
حرفيًا (`assertSame`). أي انحراف يكسر الاختبار فورًا.

## 5. عيوب حقيقية اكتُشفت وأُصلحت

1. **الخط لم يكن محمّلًا أصلًا.** `--font-sans` كان يشير إلى `'Hacen Tunisia'`
   بلا `@font-face`، فكان يعمل فقط على أجهزة مثبت عليها الخط محليًا ويسقط
   صامتًا إلى Tahoma عند كل زائر آخر. أُضيف الإعلان.

2. **مسار الخط المطلق كان سيكسر التشغيل.** `/assets/fonts/...` تحت
   `/khaledsaad/public` يشير خارج التطبيق. حُوّل إلى مسار نسبي يعمل في البيئتين.

3. **Policies لم تكن تُكتشف.** `can('run', $toolRun)` يبحث عن `ToolRunPolicy`
   لا `ProjectPolicy`، فكان كل وصول يُرفض بـ404. فُصلت إلى أربع Policies.

4. **`HasUuids` كسر ربط المسارات.** الترايت يفترض أن المفتاح الأساسي UUID،
   بينما `uuid` عمود منفصل. استُبدل بمولد في `creating`.

5. **اختبارات الصفحة العامة بلا قاعدة بيانات.** بعد ربط الصفحة بكتالوج
   الأدوات صارت تحتاج مخططًا وبيانات. أُضيف `RefreshDatabase` والبذرة.

6. **أنماط الصفحات العامة غير معرّفة.** الواجهات كانت تشير إلى
   `.catalog-card` و`.page-hero` و`.tool-hero` و`.auth-intent` وغيرها بلا أي
   تعريف في CSS. كُتبت في `resources/css/site-pages.css`.

## 7. ما يبقى خارج النطاق

هذه لم تُبنَ وهي مقصودة، لا نواقص صامتة:

1. **الأدوات السبع الباقية** — معروضة بحالة «قريبًا» صريحة.
2. **الفوترة والأرصدة** — `credit_cost` مسجل ويُعرض، لكن لا خصم ولا دفع.
3. **قراءة PDF وDOCX** — تُوسم `unsupported` بوضوح بدل تمرير نص فارغ
   يجعل النموذج يخترع محتوى غير موجود.
4. **تصدير PDF للتقرير** — العرض جاهز، المولّد غير مبني.
5. **جلسة الضيف قبل التسجيل** — الجدول موجود، الرحلة تبدأ من الحساب حاليًا.
6. **لوحة إدارة كاملة** — الموجود لوحة تكلفة الذكاء الاصطناعي فقط.
