# دليل المحتوى العربي لمنصة خالد سعد

## 1. صوت المنتج

المنصة تساعد صاحب المشروع على فهم واقعه التسويقي وترتيب أولوياته قبل زيادة الإنفاق أو التعاقد مع جهة تنفيذ. لذلك يكون صوتها:

- واضحًا قبل أن يكون لافتًا.
- تسويقيًا يشرح القيمة، لا تقنيًا يشرح طريقة عمل النظام.
- واثقًا من دون ضمان نتائج لا يمكن إثباتها.
- إنسانيًا من دون لهجة محلية أو ألفاظ متكلفة.
- عمليًا يربط كل معلومة بخطوة يمكن اتخاذها.

## 2. مستوى اللغة

تُستخدم عربية محادثية محايدة قريبة من الفصحى، مفهومة في السودان والسعودية وبقية الدول العربية. تكون الجملة قصيرة نسبيًا، ويُفضّل الفعل المباشر على الاسم المجرد.

أمثلة:

- نعتمد: «ابدأ تشخيص مشروعك».
- لا نفضّل: «ابدأ الآن» لأنها لا توضح ما سيحدث.
- نعتمد: «أضف مشروعك الأول».
- لا نفضّل: «القائمة فارغة» لأنها تصف الشاشة ولا تساعد المستخدم.

## 3. المتحدث والضمائر

- تخاطب المنصة المستخدم بصيغة المفرد المحترمة: «مشروعك»، «إجاباتك»، «يمكنك».
- يُستخدم «نحن» عندما تتحدث العلامة أو الفريق عن التزام واضح.
- يُستخدم «أنا» فقط في قسم خالد سعد أو رسالة شخصية موقعة باسمه.
- تُستخدم صياغة محايدة عندما تصف المنصة إجراءً: «اكتمل التقرير»، «تُحفظ الإجابات».
- لا تنتقل الجملة بين «أنا» و«نحن» و«النظام» داخل الرحلة نفسها.

## 4. قاموس المصطلحات

| المفهوم | المصطلح المعتمد للمستخدم | ملاحظة |
|---|---|---|
| المساحة الرئيسية بعد الدخول | لوحة التحكم | لا تستخدم «لوحة العمل» |
| نشاط المستخدم التجاري | المشروع | ثابت في الويب والجوال |
| الاستبيان الذي ينتج تحليلًا | التشخيص | «الأداة» مسموحة للإدارة فقط |
| نتيجة التشخيص | التقرير | «النتيجة الأولية» قبل إنشاء التقرير الكامل |
| العمل المطلوب تنفيذه | المهمة | الجمع: المهام |
| مستوى الاشتراك | الخطة | لا تستخدم «الباقة» للخطة |
| وحدات الاستخدام | الرصيد | الجمع عند الحاجة: أرصدة |
| رسائل الحساب | الإشعارات | ثابت بين الويب والجوال |
| التقرير المخصص للتعامل مع وكالة | موجز الوكالة الموحّد | يُختصر إلى «موجز الوكالة» إذا كان السياق واضحًا |
| التقرير الذي يراجعه شخص | المراجعة اليدوية | لا نعد بمدة ما لم تكن معلنة |
| متابعة تغير بيانات التقرير | متابعة التقرير | لا تستخدم «التقرير الحي» للمستخدم |
| بداية استخدام المنتج | ابدأ تشخيص مشروعك | لا تستخدم «ابدأ الآن» منفردة |

## 5. مصطلحات غير مفضلة

| غير مفضل في واجهة العميل | البديل |
|---|---|
| تشغيل أداة | بدء تشخيص |
| مخرجات | نتيجة / تقرير / ما ستحصل عليه |
| محرك النمو | متابعة التحسين / فرص تحسين المشروع |
| النظام يحلل | يبدأ التحليل / تُحلل الإجابات |
| البرومبت، المخطط، JSON | لا تظهر للعميل؛ تبقى في الإدارة المتخصصة |
| عندك، شغلك، جاوب | لديك، مشروعك أو عملك، أجب |
| بدون | من دون |
| لا توجد بيانات | سمِّ ما لا يوجد واقترح خطوة تالية |
| تم بنجاح | صف النتيجة: «حُفظ المشروع»، «أُضيف الرصيد» |
| مجاني بالكامل | اذكر الجزء المجاني المثبت فقط |

## 6. قواعد الصفحات التسويقية

تجيب الصفحة، بهذا الترتيب المنطقي، عن:

1. ما المشكلة التي يفهمها صاحب المشروع؟
2. ما الذي يساعده التشخيص على معرفته؟
3. ماذا سيحصل عليه؟
4. ما المطلوب منه؟
5. لماذا يثق بالنتيجة وحدودها؟
6. ما الخطوة التالية؟

يبدأ كل قسم بمعلومة جديدة. لا نكرر «اعرف أين تبدأ» بصيغ مختلفة من دون إضافة سبب أو نتيجة أو دليل.

## 7. قواعد الأزرار

- يبدأ الزر بفعل: «أضف»، «احفظ»، «ابدأ»، «راجع»، «نزّل»، «أرسل».
- يوضح الزر النتيجة إذا لم يكن السياق كافيًا: «احفظ المشروع وتابع».
- يمكن استخدام زر قصير عندما يشرح العنوان المحيط الإجراء بالكامل.
- الأفعال المالية واضحة: «اشترك — 99 ريال»، «اشترِ حزمة الرصيد».
- أزرار الحذف والتعطيل لا تستخدم صياغة ملتبسة.

## 8. العناوين

- العنوان التسويقي يبدأ من فائدة أو تحدٍ: «اعرف أين يتوقف العميل قبل الشراء».
- عنوان لوحة التحكم يصف ما يراه المستخدم: «ملخص مشاريعك وخطوتك التالية».
- لا نستخدم عنوانًا جميلًا وغامضًا يحتاج إلى شرح طويل لفهمه.
- لا تتجاوز عناوين الجوال سطرين على المقاسات المستهدفة.

## 9. النماذج والإرشادات

- اسم الحقل يطلب معلومة واحدة.
- النص المساعد يوضح الصيغة أو يقدم مثالًا، ولا يعيد اسم الحقل.
- يُذكر سبب السؤال عندما يؤثر في ثقة المستخدم أو دقة التقرير.
- الحقل الاختياري يُوسم بوضوح.
- لا نطلب من المستخدم معرفة مصطلح تسويقي متخصص لإكمال الحقل.

## 10. رسائل الخطأ والنجاح

رسالة الخطأ الجيدة تجيب عن: ماذا حدث؟ ماذا أفعل الآن؟

- نعتمد: «تعذّر عرض التشخيصات الآن. تحقق من الاتصال وحاول مرة أخرى.»
- لا نفضّل: «حدث خطأ».
- نعتمد: «الدفع الإلكتروني غير متاح حاليًا. حاول مرة أخرى لاحقًا.»
- لا نعرض تفاصيل داخلية أو أسماء خدمات أو استثناءات.

رسالة النجاح تصف الأثر:

- «أُضيف المشروع. اختر التشخيص الذي يناسب أولويتك الحالية.»
- «فُعّلت متابعة التقرير. سننبهك إذا تغيّرت البيانات التي بُني عليها.»

## 11. الحالات الفارغة

تتكون الحالة الفارغة من:

1. ما الذي لا يوجد؟
2. لماذا يهم؟
3. ماذا يفعل المستخدم الآن؟

مثال: «لا توجد تقارير لهذا المشروع بعد. ابدأ أحد التشخيصات لإنشاء التقرير الأول.»

## 12. الإشعارات والبريد

- العنوان يذكر الحدث: «اكتمل تقريرك».
- المتن يذكر العنصر المعني والأثر.
- الإجراء يصف الوجهة: «راجع التقرير والتغييرات».
- لا تستخدم الاستعجال إلا إذا كان التأخير يسبب أثرًا حقيقيًا.
- لا تحدد مدة غير مضمونة.

## 13. التقارير

- تبدأ التقارير بالخلاصة والخطوة التالية قبل التفاصيل.
- يُفصل ما تؤكده بيانات المستخدم عن المعلومات التي تحتاج إلى تأكيد.
- لا يُستخدم «تخمين» أو «اجتهاد» عندما يكفي «معلومة تحتاج إلى تأكيد».
- تنتهي التوصية بفعل محدد ومؤشر مناسب، لا بعبارة مثل «حسّن التسويق».
- تحتفظ المصطلحات المتخصصة في ملاحق الوكالة عندما يحتاجها القارئ المهني.

## 14. أمثلة قبل وبعد

| قبل | بعد | السبب |
|---|---|---|
| جرّب الآن بدون حساب | ابدأ تشخيص مشروعك | يوضح الفعل والقيمة |
| أي واحدة من هذه تحصل معك؟ | هل تصف إحدى هذه الحالات مشروعك؟ | عربية محايدة وطبيعية |
| شغّل أداة على هذا المشروع | ابدأ تشخيصًا لهذا المشروع | يبعد اللغة الداخلية عن العميل |
| لا توجد تقارير بعد | لا توجد تقارير لهذا المشروع بعد. ابدأ أحد التشخيصات لإنشاء التقرير الأول. | حالة فارغة قابلة للتنفيذ |
| التقرير الحي | متابعة التقرير | يشرح الفائدة من دون تسمية تقنية |
| حدث تعثر تقني | لم نتمكن من إكمال التحليل هذه المرة | يركز على ما يهم المستخدم |

## 15. مراجعة ما قبل النشر

- هل يفهم القارئ القيمة من أول شاشة؟
- هل يصف كل زر ما سيحدث؟
- هل توجد وعود مجانية أو زمنية أو بشرية غير مثبتة؟
- هل المصطلحات متطابقة بين الويب والجوال؟
- هل تشرح الحالات الفارغة والخاطئة الخطوة التالية؟
- هل بقيت كلمات داخلية لا يحتاجها العميل؟
- هل النص قصير بما يكفي للجوال ويحافظ على المعنى؟
