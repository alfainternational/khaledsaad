# معمارية التأسيس

## الهدف

بناء منصة عربية لذكاء وتشغيل التسويق تساعد صاحب العمل على تشخيص وضعه، إنتاج توصيات قابلة للتنفيذ، وتجهيز مخرجات واضحة قبل التعامل مع الوكالات.

## التقنية المعتمدة

- الموقع واللوحة والـAPI: PHP 8.3 + Laravel 13.
- واجهة الموقع: Blade + Tailwind CSS + Vite، مع JavaScript خفيف عند الحاجة.
- تطبيق الهاتف: Flutter 3.44 + Dart 3.12.
- قاعدة البيانات: MariaDB/MySQL عبر XAMPP على المنفذ الثابت 3306.
- المصادقة للتطبيق: Laravel Sanctum.
- الأعمال الطويلة: Laravel Queue باستخدام database driver في البيئة المحلية.
- الذكاء الاصطناعي: DeepSeek عبر طبقة خادم مستقلة قابلة لتبديل المزود.

## حدود DeepSeek

يُحفظ `DEEPSEEK_API_KEY` في ملف `.env` الخاص بـLaravel فقط. يرسل الموقع والتطبيق طلباتهما إلى API داخلي، ثم يتحقق Laravel من المستخدم والصلاحيات والمدخلات، ويرسل الطلب إلى DeepSeek، ويتحقق من المخرجات قبل تخزينها أو إرجاعها.

يجب تسجيل اسم النموذج، زمن الاستجابة، عدد الرموز، الحالة والتكلفة التقديرية من دون تسجيل المفتاح أو البيانات السرية. المهام الطويلة تنفذ في Queue، والمخرجات المنظمة تُطلب بصيغة JSON ويتم التحقق منها قبل اعتمادها.

## هيكل المشروع

- `/app`, `/routes`, `/resources`, `/database`, `/tests`: تطبيق Laravel في الجذر.
- `/mobile`: تطبيق Flutter الأصلي.
- `/docs/references`: وثائق المنتج والمراجع المحلية.
- `/docs/architecture`: القرارات المعمارية.
- `/docs/superpowers/plans`: خطط التنفيذ القابلة للتتبع.

## مراحل التسليم

1. تأسيس Laravel وFlutter وإعداد البيئة المحلية.
2. بناء الهوية والحسابات والمشاريع والصلاحيات.
3. بناء نواة التشخيص وملفات الاستعداد والتوصيات.
4. ربط DeepSeek وإدارة القوالب والاستهلاك والتكلفة.
5. تنفيذ الأدوات الإحدى عشرة على دفعات مستقلة قابلة للاختبار.
6. استكمال تطبيق Flutter والتقارير والاشتراكات ولوحة الإدارة.
