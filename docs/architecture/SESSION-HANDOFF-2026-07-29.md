## ٣. أعطال حقيقية أُمسكت (تجنّب تكرارها)

| العطل | الجذر |
| --- | --- |
| ٥٩ خطأ بعد نقل الوحدات | خريطة أصناف Composer قديمة — لم تظهر في اختبارات مصفّاة |
| مراجع غير مؤهَّلة في اتجاهين | صنف نُقل خارج نطاق مستدعيه، وآخر بقي بعد نقل مستدعيه. `php -l` يمرّرها |
| `preg_split('/\R/')` يشطر العربية | يعمل على البايتات فيطابق `0x85` داخل «م» (D9 85) |
| CRLF في ٩٤ ملفًا | Python على ويندوز يخالف `.gitattributes` |
| مفتاح خاص غير مُتجاهَل | `cpanel_deploy_ed25519` كان سيُدفع إلى GitHub |
| `parse_ratio` عشري مرة وصحيح مرة | `json_encode` يُخرج `1.0` كـ`1` — عميل Flutter ينهار |
| `hasLength(22)` ثابتًا | رقم في مكانين؛ رسالة الخطأ تكذب |
| `testProject()` أعاد Pint تسميته | مساعد يبدأ بـ`test` يُعامَل كدالة اختبار |

### فخّ تكرّر ثلاث مرات

**رمز الخروج `0` من مهمة خلفية لا يعني نجاح الأمر بداخلها** — هو رمز الغلاف.
حدث مع: `phpunit` و`vendor/` فارغ (الرسالة الحقيقية `Could not open input
file`)، وبناء APK الذي توقّف بلا `✓ Built`، وحزمة اختبارات ماتت عند ٥٧٪ بلا
سطر نهاية.

**تحقّق دائمًا من الأثر لا من رمز الخروج:** ملف مُنتَج، سطر `OK (N tests)`،
صنف يُحلّ عبر الحاوية. وخرج `cpanel-push.sh` يظهر مقتطعًا دائمًا لنفس السبب.

## ٤. ما يبقى — بالترتيب

### ١) المسح — محجوب من ضابط صلاحيات Claude Code، لا منّي

```bash
cd ~/public_html && php artisan platform:reset --backup-verified --force
```

الفحص المسبق يقول «الخادم جاهز». التجربة الجافة تعرض ٣٤ جدولًا: مشروعان،
٢٣ تقريرًا، ٢٦ تشغيل أداة، مستخدم غير إداري. يبقى: الإدارة ومساحتها،
الإعدادات، **٤ بوابات دفع كلها تُفكّ بمفتاح الإنتاج**، الخطط، الأدوات، الهجرات.

### ٢) بناء APK ونشره ورفع الحد

**البناء لم يكتمل.** رُفع الإصدار إلى `1.0.4+5` في `pubspec.yaml` و
`config/mobile.php`، وشُغِّل `flutter build apk --release` فتوقّف بعد
tree-shaking بلا سطر `✓ Built` ولا خطأ — على الأرجح مهلة. الملف في
`mobile/build/app/outputs/flutter-apk/` ما زال نسخة ١.٠.٣ (٢٨ يوليو).

أعد البناء بمهلة أطول:

```bash
cd mobile && flutter build apk --release \
  --dart-define=API_BASE_URL=https://khaledsaad.net/api --dart-define=APP_BUILD=5
```

ثم انسخه إلى `public/downloads/` وحدّث `release.json` (الحجم وsha256).

الترتيب بعدها **ملزم**: انشر الملف → دعه يصل المستخدمين → ثم ارفع
`MOBILE_MIN_SUPPORTED_BUILD=5`. عكسه يقطع الوصول عن كل حامل ١.٠.٣ دفعة واحدة.

(بعد المسح لن يبقى مستخدمو تطبيق، فيصير الرفع فوريًّا بلا ضرر.)

> **تحذير توقيع:** النسخة الحالية موقَّعة بشهادة
> `45b6a8e3…` (في `release.json`). مفتاح التوقيع مُعدّ في
> `mobile/android/key.properties`. نسخة بتوقيع مختلف **لا يمكن تثبيتها فوق
> الحالية** — تحقّق من التوقيع قبل النشر.

### ٣) دمج الفرع في `main`

`main` تقدّم بـ٧ التزامات لإعادة كتابة الأسئلة، **دُمجت في الفرع**
والمحتوى متطابق. الفرع الآن أشمل ويصلح للدمج العكسي.

### ٤) المرحلة ٢

- المحاور ١–٦ من الاستقبال · تاريخ `maturity_score` من اللقطات.
- ترقية `LiveReportChecker` من مراقبة الطزاجة إلى **تغيّر الدرجة** — هنا يولد
  الإيراد المتكرر.
- تقليص المستوى ٠ (`teaser()` جاهز، لا شاشة تستدعيه).
- **ربط مولّد الخطط بـ`LegacyCapabilities`** — الجسر جاهز ولم يُوصَل، فالخطط

## ٥. قرارات مفتوحة تحتاجك

**`owned_ratio`** — لم يُحسب عمدًا. المقام «إجمالي الجمهور المتاح» بلا مصدر
قابل للتحقق. حسابه من رقم يكتبه المستخدم يحوّل المحور ٨ من `measured` إلى
`inferred` — أي **يهدم أساس تسعيره**. المحور يبقى بتغطية صفر، والإسفين على
المحور ٧ وحده.

**`APP_KEY` الإنتاج مطابق للمحلي** (بصمة `47bb52d16e84`). تسريب نسخة التطوير
يفكّ بيانات اعتماد بوابات الدفع. تغييره يتطلب إعادة تشفير الأعمدة — قرار
منفصل بعد استقرار التحوّل.

**جلسات موازية** تعمل على المستودع نفسه. حدث مرتين: تبديل فرع في منتصف العمل،
وسباق دمج. تحقّق من `git branch --show-current` و`git log` قبل أي عمل.
