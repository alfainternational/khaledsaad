# اتساق تنسيق شاشات إدارة المحتوى

## المشكلة

تعتمد صفحة إدارة المحتوى على `form filter-bar`، لكن الحقول داخلها لا تستخدم مكوّن `.field` ولا توجد قواعد CSS خاصة بـ`.filter-bar`. نتيجة ذلك أن النموذج يبقى بعرض `34rem`، وتفقد الحقول الخام حدودها وحشوتها بسبب إعادة ضبط Tailwind، فيبتعد سهم القائمة عن النص وتظهر مساحة كبيرة غير مستغلة. النمط نفسه موجود في صفحات مشتركي المحتوى ومكتبة الوسائط، وتوجد حقول خام مشابهة في منشئ منهج الدورة. جداول وحدة المحتوى لا تعلن عقد الجدول المتجاوب، والتاريخ النسبي يظهر بالإنجليزية لأن Carbon لم يُضبط للعربية.

## القرار

سنستخدم عقدًا واحدًا داخل `workspace.css` بدل إضافة إصلاحات خاصة بكل صفحة:

- شريط مرشحات بعرض الصفحة، داخل بطاقة خفيفة، وبشبكة تتكيف من ستة أعمدة إلى عمود واحد.
- كل مرشح يحمل تسمية ظاهرة فوق الحقل؛ لا يعتمد على النص الإرشادي وحده.
- جميع حقول النماذج النصية والقوائم الخام داخل `.form` تحصل على نفس الحدود والحشوة وحالة التركيز التي تحصل عليها حقول `.field`.
- صفحات المحتوى والمشتركين والأقسام تستخدم `data-table="entity"` و`data-label` حتى تتحول الصفوف إلى بطاقات مفهومة على الهاتف.
- تضبط Carbon على العربية عند إقلاع التطبيق، فتتعرب كل التواريخ النسبية في الإدارة والتطبيق من مصدر واحد.

## النطاق

يشمل الإصلاح:

- `admin/content/index`
- `admin/content/subscribers`
- `admin/content/media`
- `admin/content/categories/index`
- `admin/content/curriculum`
- قواعد الحقول والتواريخ المشتركة التي تؤثر في بقية لوحة الإدارة.
- تجربة رفع الصورة الرئيسية والمواد المصاحبة وعرض حجمها.
- رأس صفحة المادة المنشورة عند وجود صورة رئيسية.

لا يغيّر الإصلاح أي بيانات أو عمليات حفظ أو تصفية، ولا يعيد تصميم الهوية البصرية أو التنقل.

## الصور والمرفقات

- يبقى الحد الأقصى الموحد 256 ميجابايت لكل صورة أو مرفق.
- لا يُفرض حد أدنى أو أقصى لأبعاد الصورة، ولا تُقص الصورة أثناء الرفع.
- تعرض الإدارة حجم الملف وأبعاد الصورة الفعلية قبل الرفع وبعده، وتوضح الحد بجوار أدوات الرفع.
- تبقى الصورة الرئيسية ظاهرة كصورة المادة، وتُستخدم نسخة منها أيضًا كخلفية كاملة لرأس العنوان خلف طبقة متدرجة من الأزرق الحالي لضمان وضوح النص.
- تعرض مكتبة الوسائط وصفحة القراءة حجم الملف بوحدات عربية مفهومة بدل قيمة كيلوبايت خام.

## الاستجابة

- فوق `85rem`: بحث واسع وأربعة مرشحات وزر في صف واحد.
- بين `48rem` و`85rem`: شبكة عمودين أو ثلاثة بحسب المساحة.
- تحت `48rem`: كل حقل وزر بعرض كامل، والجداول تتحول إلى بطاقات تحمل تسميات الأعمدة.

## التحقق

- اختبار عقد CSS ووجود البنية الدلالية في القوالب.
- اختبار أن Carbon ينتج نصًا عربيًا.
- اختبارات ميزة إدارة المحتوى الحالية.
- بناء Vite.
- فحص بصري لسطح المكتب والهاتف محليًا، ثم فحص HTTP وبصري للنسخة المنشورة.
