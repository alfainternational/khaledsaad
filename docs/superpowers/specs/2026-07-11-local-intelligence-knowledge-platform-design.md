# تصميم منصة الذكاء المحلي وقاعدة المعرفة

التاريخ: 2026-07-11

## 1. الهدف

تطوير منصة `khaledsaad` إلى نظام ذكاء محلي أولاً يستطيع قراءة بيانات المشاريع
والملفات، والبحث في الإنترنت، والتحليل والاستنتاج وتقديم توصيات قابلة للتتبع، مع
قاعدة معرفة منظمة تتطور باستمرار. يبقى تطبيق Laravel على الاستضافة المشتركة هو
مركز البيانات والمهام والحوكمة، بينما ينفذ عامل خاص قابل للنقل عمليات النماذج
والتضمينات التي لا تناسب موارد الاستضافة.

لا يعني "محلي" أن النموذج يعمل داخل عملية PHP على الاستضافة. المقصود أن بيانات
المنصة ومعرفتها وقراراتها مملوكة للمشروع، وأن محرك النموذج يعمل على بنية خاصة
بالمالك ولا يعتمد تشغيلياً على مزودي ذكاء اصطناعي عامين.

## 2. الواقع التشغيلي

- الإنتاج Laravel 13.5 على PHP 8.5 وMariaDB داخل CloudLinux LVE.
- حد ذاكرة PHP هو 128 MB، والرفع الافتراضي 2 MB.
- لا يتوفر Node.js أو Composer أو Redis على الخادم.
- تتوفر SSH وPython 3.9 وCron، وتعمل قائمة Laravel عبر تشغيلات قصيرة كل دقيقة.
- تشغيل نموذج لغوي قوي داخل حساب الاستضافة غير واقعي ولا يدخل في التصميم.
- الإنتاج الحالي يستخدم Gemini ثم NVIDIA، ويجب إبقاؤهما انتقالياً فقط إلى أن
  يجتاز العامل الخاص اختبارات التكافؤ والجودة.

## 3. المبادئ الملزمة

1. Laravel هو مركز التحكم ومصدر الحقيقة الوحيد.
2. العامل الخاص عديم الحالة؛ لا يحتفظ بالمعرفة الأصلية بعد إتمام المهمة.
3. لا تُعتمد معلومة بلا مصدر ونطاق وثقة وتاريخ.
4. لا تتحول نتائج الإنترنت أو النموذج إلى معرفة معتمدة تلقائياً.
5. كل معرفة معزولة حسب الحساب ومساحة العمل والمشروع، مع طبقة عامة مراجعة.
6. كل عملية ثقيلة مجزأة إلى مهام قصيرة قابلة للاستكمال وإعادة المحاولة.
7. يبقى النظام مفيداً بقواعده وبحثه النصي عند غياب العامل الخاص.
8. لا تُرسل الأسرار أو الملفات غير المطلوبة إلى أي محرك.
9. كل توصية نهائية تعرض أدلتها وحدود الثقة وما ينقصها.

## 4. البنية العامة

### 4.1 مركز التحكم على الاستضافة

يتولى تطبيق Laravel:

- المستخدمين والصلاحيات وعزل مساحات العمل.
- تخزين المستندات وبيانات المشاريع والمعرفة والإصدارات.
- إنشاء المهام وتوقيعها وتتبع محاولاتها ونتائجها.
- جلب الويب الخفيف ضمن حدود SSRF والحجم والمهلة.
- البحث النصي والترشيح الأولي وإعادة النتائج عند غياب العامل.
- مراجعة المعرفة واعتمادها أو رفضها أو إبطالها.
- السجل التدقيقي، القياسات، النسخ الاحتياطي وسياسات الاحتفاظ.

### 4.2 العامل المحلي الخاص

خدمة مستقلة تعمل أولاً على جهاز المالك، ويمكن نقلها لاحقاً إلى VPS خاص أو خادم
مؤسسي من دون تغيير عقود Laravel. تتولى:

- تشغيل نموذج محلي عبر Ollama أو واجهة OpenAI-compatible خاصة.
- إنشاء embeddings للمقاطع والاستعلامات.
- استخراج نصوص الملفات التي تحتاج أدوات أثقل أو OCR.
- إعادة ترتيب نتائج البحث دلالياً.
- التحليل متعدد الخطوات وصياغة الإجابات والتوصيات.
- إرجاع مخرجات منظمة وفق JSON Schema، لا نصوصاً حرة فقط.

يتصل العامل بالخادم اتصالاً صادراً فقط، يسحب مهاماً موقعة، ويعيد النتيجة مع
معرف النموذج وإصداره وزمن التنفيذ وبصمة المدخلات. لا يحتاج الخادم إلى فتح منفذ
وارد نحو جهاز المالك.

### 4.3 الوضع الانتقالي

يبقى `AiGatewayInterface` نقطة الدمج. يضاف مزود `private_worker` قبل المزودات
الحالية. يكون ترتيب التشغيل:

1. المحرك الحتمي المحلي داخل Laravel عندما تكفي ثقته.
2. العامل الخاص للمهام التي تحتاج نموذجاً أو embeddings.
3. Gemini/NVIDIA كاحتياط انتقالي محكوم ومقاس.
4. نتيجة محلية متحفظة عند تعذر الجميع.

لا تُعطل البوابات الحالية حتى تثبت مجموعة تقييم أن العامل الخاص يحقق عتبات
الجودة والزمن والاستقرار. بعد ذلك يصبح الاتصال الخارجي اختيارياً ومغلقاً
افتراضياً.

## 5. نموذج البيانات المعرفي

تضاف الجداول التالية ضمن حدود MariaDB، وتعد أسماؤها وعقودها هنا معتمدة:

- `knowledge_sources`: أصل المصدر ونوعه ومالكه وسياسة الثقة.
- `knowledge_documents`: ملف أو صفحة أو سجل مشروع مع البصمة وحالة المعالجة.
- `knowledge_chunks`: مقاطع قابلة للبحث مع ترتيبها ولغتها والنص المنظف.
- `knowledge_claims`: حقائق أو استنتاجات منفصلة قابلة للمراجعة.
- `knowledge_evidence`: ربط الادعاء بالمقطع أو الرابط وموضع الدليل.
- `knowledge_embeddings`: متجه، اسم النموذج، أبعاده وإصدار التضمين.
- `knowledge_relations`: علاقات يدعم أو يناقض أو يحدّث أو يشتق من.
- `knowledge_reviews`: الاعتماد والرفض والسبب والمراجع.
- `intelligence_jobs`: عقود المهام وحالتها والمحاولات والمهلة.
- `intelligence_evaluations`: نتائج الاختبارات والمقارنات بين المحركات.

كل سجل معرفي يحمل `account_id` و`workspace_id` و`project_id` عند انطباقها، إلى
جانب `visibility`, `confidence`, `valid_from`, `valid_until`, `content_hash`,
`created_by_type` وحقول التتبع. تمنع الفهارس الفريدة تكرار المصدر والبصمة داخل
النطاق نفسه.

مخزن JSON الحالي يبقى قابلاً للقراءة خلال الترحيل. تُستورد إدخالاته مرة واحدة
إلى الجداول الجديدة، ثم يصبح طبقة توافق مؤقتة قبل إزالته في إصدار لاحق.

## 6. إدخال المعرفة

### 6.1 بيانات المشاريع

تحول بيانات المشروع والأدوات والتقارير والتنفيذ إلى وثائق معرفة ذات نوع واضح.
عند التعديل، تُنشأ نسخة جديدة أو تُبطل المقاطع المتأثرة فقط. لا يعاد فهرسة كل
المشروع دون حاجة.

### 6.2 الملفات المرفقة

يدعم الإصدار الأول: PDF النصي، DOCX، XLSX، CSV، TXT، Markdown، JSON والصور.

مسار المعالجة:

1. تحقق من النوع الحقيقي والحجم والامتداد ومكافحة الأسماء الخطرة.
2. تخزين خاص خارج `public` مع اسم مولد وبصمة SHA-256.
3. إنشاء مهمة استخراج منفصلة.
4. استخراج النص والبنية والجداول مع تسجيل صفحات أو مواضع المصدر.
5. تنظيف المحتوى وتقسيمه بمقاطع تحافظ على العناوين والسياق.
6. فحص الحقن التعليمي؛ محتوى المستند بيانات غير موثوقة لا تعليمات نظام.
7. توليد embeddings واستخراج الادعاءات المرشحة.
8. عرض حالة المعالجة والأخطاء وإمكانية إعادة المحاولة.

يستخدم رفع مجزأ بحجم 1 MB للجزء، مع حد افتراضي 50 MB للملف قابل للخفض من
الإدارة. يجمع الخادم الأجزاء خارج `public` ويتحقق من البصمة قبل إنشاء مهمة
الاستخراج؛ لذلك لا يعتمد المسار على رفع حد PHP العام.

### 6.3 الإنترنت

يُفصل البحث عن الجلب وعن الاعتماد:

- البحث يعيد عناوين وروابط ومقتطفات.
- الجلب يقرأ صفحات مختارة فقط بحد أقصى للحجم والتحويلات والوقت.
- الاستخراج يحفظ النص وبصمة الصفحة وتاريخ الجلب والعنوان واللغة.
- التحقق يقارن مصدرين مستقلين عند الادعاءات المتغيرة أو المهمة.
- التعارض يبقى ظاهراً ولا يحسمه النموذج بلا دليل.
- لكل مصدر سياسة ثقة، ويعاد جلب المحتوى المنتهي الصلاحية.

يبقى `RemoteUrlGuard` أساس حماية SSRF، وتضاف حماية إعادة ربط DNS، وحدود الحجم
ونوع المحتوى وسياسة robots ومعدل الطلبات. لا يعتمد البحث على HTML هش وحيد؛
يحتفظ `WebSearchGateway` بعقد يسمح بإضافة SearXNG خاص لاحقاً.

## 7. الاسترجاع والتحليل

الاسترجاع هجين على مرحلتين:

1. ترشيح MariaDB بحسب النطاق والصلاحية والنوع، ثم بحث FULLTEXT وكلمات مفتاحية.
2. إعادة ترتيب أفضل المرشحين بالتضمينات عبر العامل الخاص عند توفره.

تُدمج الدرجة من صلة النص، والتشابه الدلالي، وثقة المصدر، وحداثته، واعتماده.
لا تعني درجة التشابه وحدها صحة المعلومة.

يستقبل محرك التحليل حزمة أدلة محدودة، ويعيد:

- الإجابة أو التوصية.
- الاستنتاجات الوسيطة المنظمة، من دون كشف تفكير داخلي خام.
- الاستشهادات المرتبطة بكل ادعاء.
- درجة الثقة وأسباب خفضها.
- المعلومات الناقصة والأسئلة اللازمة.
- الإجراءات المقترحة ومؤشرات القياس.

## 8. التعلم والتطوير المستمر

التعلم ليس إعادة تدريب تلقائية للنموذج. هو دورة معرفة محكومة:

1. التقاط مصدر أو نتيجة استخدام.
2. إزالة التكرار وربطها بنطاقها.
3. استخراج ادعاءات مرشحة.
4. التحقق من الأدلة والتعارض والحداثة.
5. اعتماد آلي فقط لحقائق المشروع المنقولة حرفياً من حقول موثقة يملكها المستخدم؛
   أما ادعاءات الويب أو استنتاجات النموذج فتبقى مرشحة حتى مراجعة بشرية.
6. قياس أثر المعرفة على جودة الإجابات.
7. خفض الثقة أو الإبطال عند ظهور دليل أحدث.

تُحدّث أوامر `ai:learn`, `ai:distill` و`ai:teach` لتكتب في النموذج المعرفي
الموحد. لا تُقبل مخرجات المعلم لمجرد أنها JSON صالح؛ يجب أن تحمل أدلة واختبار
عدم التلوث وعدم التكرار.

## 9. الأمن والخصوصية

- مصادقة العامل بمفتاح عام/خاص أو HMAC مع nonce ووقت انتهاء وتدوير مفاتيح.
- تشفير الأسرار وعدم تخزينها داخل سجلات المهام.
- منع وصول العامل إلى مهمة خارج النطاق المصرح له.
- روابط تنزيل قصيرة العمر، واستخدام البصمة للتحقق من الملف.
- تنظيف السجلات من بيانات المستخدم والمفاتيح.
- سجل تدقيقي لكل جلب وتحليل واعتماد وحذف.
- حذف متسلسل وآمن لمعرفة المشروع عند طلب الحذف.
- قوائم أنواع وأحجام مسموحة، وفحص أرشيفات الضغط والقنابل النصية.
- عدم تنفيذ أي نص أو كود مستخرج من ملف أو صفحة.

## 10. التشغيل على الاستضافة المشتركة

- تستخدم قاعدة البيانات للـ queue والكاش عند الحاجة.
- كل مهمة خادم قصيرة، قابلة للاستكمال، ولها حد ذاكرة ووقت ومحاولات.
- Cron الحالي يشغل `queue:work --stop-when-empty --max-time=55` ويستمر كأساس.
- لا تعتمد الخطة على daemon أو Redis أو Docker أو Node.js في الإنتاج.
- تبنى أصول Vite محلياً ثم ترفع كاملة وفق مسار النشر الحالي.
- تضاف لوحة صحة تعرض تراكم المهام، العامل المتصل، زمن آخر نجاح، فشل الاستخراج،
  حجم المعرفة، حداثتها ونسبة الادعاءات غير المراجعة.

تُعالج مهام `CaptureMonitoringSnapshotJob` الفاشلة الموجودة قبل توسيع حمل
الـ queue، ويضاف تنبيه عند تراكم أي نوع من المهام.

## 11. تجربة المستخدم

يضاف داخل المشروع قسم "المعرفة" يوفر:

- رفع الملفات ومتابعة حالة تحليلها.
- إضافة روابط أو طلب بحث ويب.
- استعراض المصادر والادعاءات والتعارضات.
- اعتماد المعرفة أو رفضها وإبطالها.
- سؤال المشروع مع إظهار الأدلة والثقة.
- معرفة ما إذا كانت الإجابة محلية حتمية أو من العامل الخاص أو من احتياط خارجي.

لا تعرض الواجهة تفاصيل تقنية للنموذج للمستخدم العادي، بينما تعرض لوحة الإدارة
التشخيص الكامل والتكاليف والأزمنة والإصدارات.

## 12. حالات الفشل

- غياب العامل: تبقى المهمة معلقة ويعمل البحث النصي والمحرك الحتمي.
- انتهاء المهلة: تعاد المحاولة بحد أقصى ثم تعرض حالة واضحة.
- ملف غير قابل للاستخراج: يحتفظ بالملف ويطلب OCR أو صيغة بديلة.
- مصدر ويب محجوب: يسجل السبب ولا يعامل الغياب كحقيقة.
- تعارض مصادر: يعرض الطرفين ويمتنع عن التوصية الجازمة.
- فشل النموذج في عقد JSON: محاولة إصلاح واحدة ثم رفض النتيجة.
- تغير نموذج embeddings: إعادة فهرسة تدريجية بإصدار جديد دون تعطيل القديم.

## 13. الاختبارات ومعايير القبول

### 13.1 اختبارات آلية

- عزل المعرفة بين الحسابات ومساحات العمل والمشاريع.
- منع التكرار وإدارة الإصدارات والإبطال.
- رفع كل نوع مدعوم ورفض الأنواع والحجوم الخطرة.
- استخراج المقاطع مع مواضع مصدر صحيحة.
- حماية SSRF وإعادة ربط DNS والتحويل إلى عناوين خاصة.
- البحث النصي والدلالي والاسترجاع عند غياب العامل.
- توقيع المهام ومنع replay وانتهاء الصلاحية.
- retries وidempotency واسترداد المهام المتوقفة.
- عدم تحول محتوى الملفات إلى تعليمات للنموذج.
- بقاء الاختبارات الحالية، ومنها خط الأساس 94 اختباراً و602 تحقق، ناجحة.

### 13.2 مجموعة تقييم الجودة

تنشأ مجموعة عربية ثابتة، لا تقل عن 100 حالة، تغطي:

- فهم نية المستخدم وإعادة الصياغة.
- تحليل مشاريع من قطاعات مختلفة.
- أسئلة تحتاج أكثر من مستند.
- مصادر متعارضة أو قديمة.
- توصيات يجب أن ترفض التخمين.
- بحث حديث مع استشهادات.
- ملفات عربية وجداول وصور.
- محاولات حقن تعليمات داخل المستندات.

تسجل لكل حالة: صحة الادعاءات، اكتمال الأدلة، دقة الاسترجاع، فائدة التوصية،
الامتناع الصحيح، الزمن والتكلفة. لا يغلق الاحتياط الخارجي حتى يحقق العامل الخاص:

- صفر تسريب بين المشاريع في الاختبارات.
- 100% استشهاد للادعاءات المبنية على المصادر.
- دقة استرجاع Top-5 لا تقل عن 85% على مجموعة التقييم.
- صحة حقائق لا تقل عن 90%، وامتناع صحيح لا يقل عن 90%.
- نجاح عقود JSON لا يقل عن 98% بعد محاولة الإصلاح المسموحة.
- عدم وجود تراجع في اختبارات النظام الحالية.

## 14. مراحل التنفيذ

1. إصلاح خط الأساس التشغيلي ومهام الإنتاج الفاشلة، وإضافة القياسات.
2. بناء مخطط المعرفة الموحد وطبقة التوافق مع JSON الحالي.
3. بناء إدخال ملفات نصية ومشاريع مع البحث النصي والاستشهادات.
4. بناء بروتوكول العامل الخاص والتوقيع وإدارة المهام.
5. إضافة embeddings والاسترجاع الهجين وإعادة الترتيب.
6. ترقية البحث الويب والتحقق والتحديث الدوري.
7. إضافة تحليل الصور وOCR والملفات الجدولية المتقدمة.
8. إنشاء مجموعة التقييم وتشغيل المقارنة ثم تقليل الاعتماد الخارجي تدريجياً.
9. نشر كل مرحلة خلف Feature Flag والتحقق على الاستضافة قبل توسيعها.

## 15. خارج النطاق حالياً

- تدريب نموذج لغوي من الصفر.
- تشغيل LLM داخل عملية PHP أو حساب CloudLinux المشترك.
- السماح للنظام بتعديل كود الإنتاج أو تنفيذ توصيات مالية تلقائياً.
- حذف مزودي الذكاء الحاليين قبل إثبات البديل.
- قاعدة متجهات مستقلة تتطلب daemon؛ يمكن إضافتها بعد الانتقال إلى VPS.

## 16. تعريف الاكتمال

لا يعتبر الهدف مكتملاً بمجرد وجود شاشة أو جدول. يكتمل عندما تعمل الرحلة كاملة
على الإنتاج: إدخال مشروع أو ملف أو رابط، استخراج وفهرسة، استرجاع الأدلة، تحليل
خاص، توصية موثقة، مراجعة معرفة، تعلم لاحق، وتعافٍ من غياب العامل، مع اجتياز
مجموعة القبول وعدم الاعتماد الإلزامي على أي مزود ذكاء خارجي.
