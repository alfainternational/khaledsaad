# تصميم استكمال الذكاء التشخيصي الموحد

## القرار

هذه المواصفة تصحح فجوات التنفيذ عن تصميم الاستشارة الذكية المعتمد في
`2026-07-26-unified-smart-consultation-release-design.md`. لا تنشئ منتجًا جديدًا؛ بل تجعل
التشخيصات الفردية، والاستشارة الذكية، والأدلة، والاستنتاجات، والتعارضات، والتقارير تعمل
فوق معرفة واحدة للمشروع في Laravel، ويستهلك الويب وFlutter عقد API واحدًا بلا فروق.

## مصدر الحقيقة

تبقى `project_answers` هي القيمة الحالية المتوافقة مع النظام القائم، ويضاف سجل مصادر
تاريخي غير هدّام لكل قيمة. يسجل المصدر، والقيمة، والثقة، والفترة، ومعرف الجلسة أو التشغيل،
وتاريخ الرصد. لا تمحى القيمة القديمة عند ورود قيمة جديدة، بل يتغير المعتمد مع بقاء تاريخ
المصادر قابلًا للتدقيق.

كل كتابة من ملف المشروع أو أداة أو استشارة تمر عبر خدمة معرفة واحدة. وكل أداة واستشارة
تقرأ القيمة المعتمدة نفسها؛ لذلك لا يتكرر السؤال، ويُعرف سبب اعتماد الإجابة ومصدرها.

## سياق الاستشارة والأدلة

تستخرج مرفقات الاستشارة بنفس محرك استخراج مرفقات الأدوات، مع حالة استخراج واضحة وبصمة
SHA-256. يدخل النص المستخرج، ضمن حد آمن، في سياق جميع تشغيلات الأدوات التابعة للجلسة.
وتدخل كذلك الحقائق، والمعلومات الناقصة، والاستنتاجات، والتعارضات المفتوحة والمحسومة،
وقرارات الحسم. لا يتحول الملف أو الاستنتاج إلى حقيقة صامتة؛ يحتفظ كل عنصر بنوعه وثقته.

يرتبط كل `tool_run` بدأته الاستشارة بمعرف جلستها. يبني `ProjectSnapshotBuilder` سياقًا
موحدًا يحتوي ذاكرة المشروع، وسياق الاستشارة، وأحدث نتائج الأدوات الأخرى المنشورة، بحيث
تستفيد الأداة من معرفة المنصة السابقة من دون اعتماد دائري على نتائج دفعتها الجارية.

## تركيب التقرير

ينشأ تقرير الوكالة من أحدث تقارير الأدوات ومن سياق الاستشارة المحدد صراحة. يضاف إلى
اللقطة قسم `consultation` يشمل النطاق، والحقائق، والافتراضات، والفجوات، والأدلة،
والتعارضات وقراراتها. ويضاف قسم `cross_tool_synthesis` يجمع نتائج الأدوات بأسمائها
ومصادرها، ويظهر الاتفاقات والاختلافات بدل دمجها في ادعاء مجهول المصدر.

تظل تقارير الأدوات والتقارير الموحدة إصدارات تاريخية غير قابلة لإعادة الكتابة. يحسب
الخادم حداثة كل تقرير بمقارنة وقت لقطة مصادره بآخر تغيير مؤثر في معرفة المشروع أو أدلته
أو نتائج أدواته. يعرض الويب والتطبيق الحالة نفسها: حديث، أو يحتاج تحديثًا مع الأسباب،
ويستخدمان عملية التوليد القائمة لإنشاء إصدار جديد.

## التوافق والخصوصية

- ترحيلات إضافية فقط، مع تعبئة سجل المصادر من `project_answers` الحالية.
- حذف جلسة الاستشارة يفصل التقرير التاريخي كما يحدث حاليًا، ويحذف ملفات الجلسة فقط.
- التقرير ذو إخفاء الأدلة لا يعرض النص المستخرج أو موضع الملف، في الويب أو API أو PDF.
- لا ترسل النصوص الحساسة إلى القياس أو السجلات التشغيلية.
- السجلات القديمة التي لا تحمل جلسة تبقى صالحة، وتظهر بسياق أدواتها وذاكرة المشروع.

## عقد التكافؤ

Laravel يحسب السياق، والحداثة، والتجميع. Blade وFlutter يعرضان القيم نفسها ولا يعيدان
الحساب. تشمل واجهات الاثنين: حالة الاستخراج، قائمة المصادر، سياق الاستشارة في التقرير،
الاتفاقات والاختلافات بين الأدوات، حالة حداثة التقرير، وإجراء إنشاء إصدار محدث.

## معايير القبول

1. إجابة أي مسار تصل إلى المسارين الآخرين مع مصدرها، ولا يكرر السؤال المعروف.
2. مرفق الاستشارة يستخرج فعليًا ويدخل لقطة تشغيلات الجلسة والتقرير وفق الخصوصية.
3. الاستنتاجات والتعارضات والحسم تظهر في التقرير الموحّد ونسخة PDF وFlutter.
4. نتيجة أداة منشورة تدخل سياق تشغيل لاحق لأداة أخرى وتظهر بمصدرها في التجميع.
5. تعديل معرفة مؤثرة يجعل التقرير السابق «يحتاج تحديثًا» من API والويب والتطبيق.
6. إنشاء تقرير جديد لا يغير التقرير التاريخي السابق.
7. اختبارات Laravel وFlutter والبناء ومصفوفة التكافؤ وفحص الإنتاج كلها ناجحة.
